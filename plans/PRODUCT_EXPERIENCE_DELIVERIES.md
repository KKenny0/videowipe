## 目标、取舍和共同边界

目标是缩短“选中视频到得到愿意使用的成片”的总时间，包括等待、判断和返工。三次交付分别解决首次成功、等待与恢复、修正与复查；任一交付完成后产品都能独立使用。

最小方案是只调整当前页面、自动填入有效试擦时间、完成后原地播放。将它作为交付一；后续能力只有明确的等待、恢复或返工收益才进入运行时。

- 保留 Python + FastAPI + 原生 HTML/JS，不引入 React、数据库、队列服务、账号或云端 API。运行时代码只放 src/videowipe，维护验证放 scripts。
- 保留 STTN、现有权重与精度、640×120 输入、gap=25、ref_length=5、neighbor_stride=5；自动 MPS 和空目标段带跳过已实现，不重复建设。
- 保留单个本地任务执行槽和串行模型调用。试擦、全片处理与重试均由用户明确启动。
- 交付一、二保留 WipePlan v1；交付三为明确保护区域引入按需使用的 v2，不能把 keep 偷换成强保护。
- 新增 HTTP 能力仅用于本地网页；无新增 CLI 命令、环境变量、密钥或第三方账号。已有 FFmpeg/ffprobe 路径已查到且可运行，版本为 8.1。
- 全程保留原文件和上一次成功结果；导出先写新运行目录，成功校验后才更新“当前结果”引用。失败、取消和崩溃都不发布半成品。
- 首批验收限定当前支持路径：内置 STTN、可正确解码的恒定帧率 SDR 视频。HDR、可变帧率、外部模型的新增编辑能力不做隐式兼容承诺；输入检查发现未覆盖特性时明确提示。
- 这是跨越八个以上文件的工作，三阶段预计累计涉及约 18–22 个运行时、测试、文档和验证文件。每次交付单独审查、提交与回退，不要求一次改完。

总体数据流：

~~~text
网页：选片 / 目标 / 时间 / 对比
           | 请求及审阅版本
           v
FastAPI + Job —— 任务清单 / 审阅快照 / 已成功产物
           |
           v
WipeEngine —— planning / WipePlan 校验与投影
           |
           v
STTN 分段预测 —— 交付三的有界预测缓存
           |
           v
原片合成 + FFmpeg 新结果 —— 网页播放及下载
~~~

网页不能直接绕过引擎调用模型。缓存不保存用户决定；WipePlan 是执行决定的来源。

## 交付一：顺手完成第一次清理

预计 4–6 个工程日，含原型、实现和真实视频验收；是工作量估计，不是日期承诺。

### 操作与页面

1. 先交付 designs/cleanup-workspace/index.html 可点击原型，覆盖普通字幕、片头无字幕、多个目标、试擦失败四条路径；包括 1280×800、390×844、键盘操作和明暗配色。原型只使用本地示例，明确模拟处理，不展示虚构的真实推理结果。原型确认后再替换产品页面。
2. 选片后主区域立即用浏览器本地文件 URL 播放；换片和离开时释放 URL。浏览器不支持源编码时显示“此格式暂不能在浏览器预览”，仍允许检测，保留已有代表帧入口；不在本阶段增加代理视频转码链。
3. 任务开始后收起介绍区。视频、目标和主按钮在桌面首屏可见；窄屏按播放器、主按钮、目标顺序排列。目标显示裁剪图、位置/标签和秒数，不以 ID、帧号作为主文案；未选中的目标也能定位查看。
4. 每个目标使用已记录的 presence_frames 选首个实际出现帧；没有存在帧的人工/回退候选标注“位置参考”。同帧多个目标共用一次帧提取。图片由原片对应帧生成并缓存在任务目录，不能用不含该目标的统一截图冒充证据。
5. 自动试擦规则固定：对已选轨道的有效 segments 求并集，取最长连续区间，长度相同时取最早；选其中部的 3 秒窗口，区间不足 3 秒则围绕它取最多 3 秒并裁到片长内。使用统一的秒→帧转换校验，最终窗口必须含非零执行遮罩。用户改选择后只重算尚未手动指定的推荐时间。无目标时不启用试擦，并显示原因。
6. 主按钮依次为“检测目标”“先看这 3 秒效果”“满意，处理全片”。保留“直接处理全片”和手动 3/5 秒入口；试擦完成不自动执行全片。沿用已有编辑使旧试擦失效的规则。
7. 试擦继续使用现有单文件上下同步对比。完成后在原工作区播放正式结果，默认回到最近试擦时间。提供暂停状态下的原片/结果切换；切换先等待对应时间定位完成，避免错帧。此阶段不承诺两个独立播放器连续播放时逐帧同步，已有单文件试擦用于严格同步检查。
8. 保留原上传文件的展示名，下载名为原文件 stem 加 _clean.mp4；存储名仍为服务端生成的安全文件名。控制字符、分隔符及超长名称规范化。消费已有 warnings，使用“需留意”提示，不生成质量评分。

### 接口和文件

- GET /jobs/{id}/source-video：仅返回该任务原片，支持 FileResponse/Range；不能传入任意路径。
- GET /jobs/{id}/result-video：仅返回已成功结果，独立于附件下载响应。
- GET /jobs/{id}/frame?frame_index=N：整数帧边界校验、限定任务源文件，返回实际定位到的帧；无法可靠定位时报错，不以邻帧充数。
- 现有 preview 响应增加 source 的尺寸、fps、frame_count、目标 evidence_frame 和 recommended_trial；前端现有接口继续可用。
- 原文件名进入 Job.snapshot；现有 trial/confirm 的 selected_ids 和 bbox_overrides 保持兼容。
- 主要文件：web/index.html、server/app.py、server/jobs.py、tests/test_server.py、tests/test_trial.py、README.md、README_CN.md，以及原型文件。展示逻辑留在现有页面，暂不拆组件系统。

### 验收与回退

- 四条原型路径都能走通，按钮和焦点顺序可理解；原型确认是进入 UI 实施的明确检查点。
- 字幕第 12 秒才出现的素材，无需输入时间，一次点击即可试擦有效画面；覆盖不足 3 秒、片尾、多个不连续区间、空选择。
- 更改目标、框或时间后旧结果不能冒充新设置；试擦失败仍能直接重试。
- 成功结果可在页内播放、寻址、听声音、切回原片和下载；中文文件名正常，路径字符不能影响存储位置。
- make check；真实 FFmpeg/Range 检查；三条现有素材的自动检测→试擦→全片路径；桌面、窄屏、键盘、明暗视觉验收。此次不修改掩码语义。
- 回退产品 UI/API 改动即可，新增展示字段可忽略，不修改原片或原 WipePlan。

## 交付二：减少等待和重新开始

预计 7–10 个工程日。按下面顺序合入，每个小步完成后原有完整细化流程仍可使用。

### 2A 提前审阅，不提前执行未细化计划

- WipeEngine.plan 增加可选 on_candidates 回调，默认 None。回调只接收独立的元数据快照：source、候选 ID/bbox/标签/presence_frames、默认选择和证据图引用；不暴露 detector、可变 mask 或内部 CleanPlanDraft。
- 在 prepare 完成、已有候选产物写好后调用回调，再继续原来的全片 refine。回调遵循现有进度回调异常处理约定，不吞掉调用方异常。
- Job.state 在此期间仍为 pending，新增 review_ready 布尔量和 phase=refine。网页开放目标查看与编辑，并显示“目标可审阅，正在确认出现时间”；试擦/全片按钮在 final_plan_ready 前禁用。
- 审阅修改放在独立 overrides 中，以 candidate ID 和 revision 绑定。细化完成只替换机器证据，不改写这些 overrides；若目标证据消失或时间变空，标出冲突，禁止静默执行。
- 对由 keep 改为 remove 的候选，在下一次实际执行前补齐其粗时间窗口内的原规则细化；复用已经得到的逐帧检测框。执行不接受未经相应时间检查的新选目标。
- 本次明确不做“仅细化试擦区域”。它会影响全局候选状态和推理裁剪带；先把早审阅、重叠利用用户判断时间的收益独立交付。性能报告不得将早审阅表述成模型试擦已经更快。

### 2B 任务保存、取消与重试

- 每个新任务保存 job.json，schema_version=1。内容固定为任务 ID、原文件展示名与相对路径、source SHA-256、state/phase、review_revision、机器计划目录、用户 overrides、成功结果引用、最新试擦引用、warnings/error 和更新时间。
- 保存使用同目录临时文件、flush/fsync、os.replace；计划 JSON/NPZ 先写入新的不可变 revision 目录，全部完成后再原子更新清单引用，避免新 JSON 配旧 NPZ。任务清单是重启恢复依据，sessionStorage 只保存任务 ID。
- jobs 根下保存 last_job.json，仅引用一个任务 ID；启动只恢复这一项，不自动扫描或导入历史无清单的 jobs。所有清单路径必须是任务目录内相对路径，拒绝路径逃逸、符号链接越界、未知版本和损坏内容；不使用 pickle。
- 成功试擦和成功全片在重启后仍能打开。若重启时任务为运行中，恢复为 interrupted，不自动执行；有完整计划则回到审阅/重试，没有完整计划则重新检测。保留旧草稿供查看，但重新检测后必须核对候选证据，不能按碰巧相同的 ID 自动套用旧框。
- PATCH /jobs/{id}/review 接受 expected_revision 和完整 overrides，校验后 revision 加一并保存。前端在一次编辑手势结束时保存，处理按钮等待保存成功；旧 revision 返回 409 并要求刷新当前决定。试擦与全片记录固定审阅版本，迟到结果不切换当前显示。
- POST /jobs/{id}/cancel 将每任务 CancellationToken 置位；立即返回 cancelling，实际工作退出前继续占用执行槽。安全边界退出后回到可审阅状态；检测尚无完整计划时显示已取消并允许重新检测。服务端正确识别取消异常，不能当普通错误丢失选择。
- POST /jobs/{id}/retry 只接受失败/中断的已有任务，依据失败阶段从检测或使用现有计划的全片处理重新开始；新运行目录、新 token，绝不覆盖成功文件。重复点击使用 operation_id 去重，不启动第二个工作线程。
- 原有 DELETE /jobs/current 保留既有语义；新页面使用新的取消端点。关闭网页不等于取消计算。

### 2C 复用试擦与真实进度

- 每任务最多保留 3 个可复用试擦、总计最多 128 MiB，只清理本功能管理的试擦缓存，不删除源片、正式结果或既有未知产物。用户仍在播放或当前显示的文件不参与驱逐；暂时没有可驱逐项则本次不缓存。
- 缓存键为源 SHA、规范化后的实际执行计划/遮罩、帧区间、权重 SHA、实际后端/设备/数值精度、gap/ref_length/neighbor_stride、羽化、输出编码参数与推理实现版本。比较执行内容而非 revision 数字，才能让改回原设置命中。
- 查找发生在计划完成细化及实际后端已解析之后；不能为了提前返回而用尚未知的权重或默认设备组成缓存键。只缓存完整、已校验成片。
- SSE 的 onerror 不主动 close，利用 EventSource 自带重连；连接状态为“正在重新连接”。onopen 后读取一次完整任务快照，终态才 close；服务返回 404 时终止恢复并保留本地说明。事件携带完整快照，无需事件重放服务。
- 显示复制文件、检测目标、确认时间、修复、编码完成等实际阶段。进度记录 phase/completed/total，禁止把阶段百分比伪装成全流程百分比。
- 至少完成 3 个可比较分段后，用当前运行已完成分段吞吐估算本阶段剩余时间区间；进入另一阶段清空估算。没有可靠统计时显示处理帧数，不给假倒计时。
- 补齐安装说明：Apple Silicon 的网页推荐源码安装 .[web,torch]，其他 CPU 环境保留 .[web,onnx]；设备显示取实际加载结果，首次权重下载显示准备状态。不上桌面安装器。

### 接口、文件、验收与回退

- SDK 仅增加上述可选 on_candidates；WipeRequest 及 WipePlan v1 保持兼容。新增 HTTP review/cancel/retry 及 playback 播放引用保护；原 trial/confirm 请求新增可选 expected_revision、operation_id，新页面必须发送，旧客户端字段缺省仍走原来的单任务校验。
- 主要涉及 engine.py、planning.py、detect.py（保留可复用细化检测框）、server/app.py、server/jobs.py、web/index.html、weights.py，以及现有 tests/test_server.py、tests/test_trial.py、tests/test_boundaries.py。清单读写先放 jobs.py，不设 Repository/Store 抽象。
- 新增维护脚本 scripts/verify_cleanup_journey.py：mode=journey，记录选择文件、复制结束、候选可审阅、精修完成、首段可播放、全片可播放时间；区分冷启动、热启动、缓存命中。可运行命令见统一验收部分。
- 真实三样本加一条由 english1 重复生成的 10 分钟压力素材：候选可审阅必须先于 refine 完成；同设置二次试擦模型调用为零；缓存键任一执行因素改变不能误命中；未命中普通全流程三次中位数退化不超过 5%。长素材只证明时长/资源行为，不代表真实长视频内容多样性。上述工程门槛已通过；普通三样本三轮中位数退化分别为 1.8%、1.0%、0.6%，长素材三轮完成。原始记录见 result/product-journey/report.json 和 result/product-journey-long/report.json。
- 覆盖断网重连、跨标签页旧版本、连续取消/重试、检测/编码失败、取消期间上传另一任务、服务重启、损坏清单、计划对写入中断、源片替换、缓存不足。等待计算真正退出后才释放单任务槽。
- 回退后 v1 计划仍可由旧引擎执行，原视频和成功结果均保留；旧版忽略新清单，不承诺旧 UI 能恢复新任务。恢复能力不等于推理断点续算。

## 交付三：减少全片返工

复查定位、时间与保护编辑、分段预测复用已实现。三样片三轮门槛通过后，网页默认开启复用；SDK 仍由 prediction_cache_dir 显式开启。工程验证、最终实现复核与画质限制见交付三报告。多语样片存在明显残字，不宣称画质已达标。

### 3A 有依据的复查位置

- 复查列表只使用确定证据：每条已处理轨道的首次/末次生效边界、用户手动标记的位置、已有处理 warnings 能对应的帧。它是导航建议，不是异常判定。
- 边界前后各取最多 1 秒作为检查窗口；相邻窗口合并，边界、目标 ID 和建议原因保留。单次默认展示最多 12 项，先列用户标记和警告，再列首次/末次边界；仍可逐目标展开其他边界。
- 点击后原地定位、循环播放该窗口，支持“看过了”“标记问题”；结果和审阅状态绑定 result revision。新结果只有不受编辑影响的人工标记可以保留，机器建议重新计算。
- 不在这次三阶段计划中交付 OCR 残留分数、闪烁分类器或自动重擦。它们缺少已校准的质量依据；后续单独通过带人工标签的数据评估后再立项，不能作为本次未完成占位项。

### 3B 时间修改和明确保护

- 允许为现有 remove 目标编辑半开帧区间，在界面按秒显示。所有 seconds→frame 的规则继续复用试擦转换；排序、去重、合并区间，拒绝越界、非有限时间与空区间。每次编辑可撤销，恢复直接重放上一份审阅快照。
- 新增“保护这里”：手画静态矩形及生效时间段。它表示这些像素必须来自原片，具有高于 remove 的优先级。keep 继续只表示不主动删除该候选。
- 仅包含 remove/keep 的计划继续保存 v1；有 protect 轨道的计划保存 v2。v2 复用现有 Track 的 bbox、mask、segments 与 NPZ 形式，只新增合法 action=protect。加载器支持 v1/v2，拒绝未知版本；protect 必须有合法非空 mask 与时间段。
- 对每帧先合并 remove 遮罩并按现有规则羽化，再把活跃 protect 像素的 alpha 置零。保护区内部在编码前必须逐像素等于原片。is_temporal、execution_masks、predicted_mask_at、remove_union_mask 的定义和所有调用方同步更新：时间无关 union 必须按全部区间边界求实际可能被处理的像素并集，不能把局部时段保护误当全程保护。
- 全局裁剪带由全时间有效执行范围确定；每帧仍按实际 alpha 合成。若全片有效移除区域为空，页面提示“没有需要处理的区域”，禁止启动空模型任务。
- 外部模型/ProPainter 不接受含保护语义的 v2，明确报能力不支持，不能扁平化。旧版引擎遇到 v2 会拒绝；原 v1 基础计划另存保留，绝不把保护丢掉后无提示执行。
- 沿用交付二 PATCH /jobs/{id}/review，overrides 新增 segment_overrides 和 protections；仍要求 expected_revision。执行前编译成独立 WipePlan revision，保护编辑不写回检测证据。
- 新增 GET /jobs/{id}/mask?frame_index=N&revision=R，返回该审阅版本实际执行 alpha 的 PNG，含羽化和保护结果。网页用它叠加“实际处理范围”；编辑保存完成前显示正在更新，不能用框或前端模拟羽化冒充真实遮罩。旧版本响应不得盖住新编辑。

### 3C 复用分段预测，从原片重新合成

确定的技术路径：缓存 _process_segment 输出的 640×120 uint8 预测，而不是缓存最终 MP4。该函数不接收掩码；在源帧和裁剪范围相同时，改变时间选择或保护区可以复用预测，重新做遮罩合成即可。

- WipeRequest 新增可选 prediction_cache_dir，默认 None；Web 由服务端绑定为当前任务的专属缓存目录，不接受 HTTP 传入文件路径。透传到 InpaintJob，由 STTN 独占使用；外部模型明确拒绝该选项。
- 缓存单位为一个全局 gap × 一个裁剪带，保存精确 uint8 数组及有效帧标记，使用 allow_pickle=False。不存整片高分辨率帧，不存 GPU tensor。
- 预测键包含 source SHA、全局 start/end、裁剪带 top/bottom 与源尺寸、640×120、权重 SHA、后端与设备/精度、参考帧参数、预处理/推理实现签名。现有逻辑下 mask 不影响模型输入，因此不进入预测键；mask 与羽化仍必须进入交付二的最终试擦成片键。
- 每次依据新计划重新计算实际裁剪带和活跃段。只有上述预测键完全一致才复用；框移动导致裁剪带变化、权重变化、缓存缺失或损坏时，重新计算对应项。不给“修改任意一秒永远只计算一秒”的保证。
- 单任务上限 512 MiB，所有本功能预测缓存合计 2 GiB；满额停止收录新项，已有命中仍可读，未命中正常推理。用户可以单独清除当前任务缓存。容量不足不得导致清理失败，也不得自动删除输入或正式输出。此处故意采用固定上限，避免构建通用缓存管理系统。
- 完整结果始终从原始源视频逐帧读取，合成新 alpha，并用现有 FFmpeg 参数重新编码一次。旧成片不作为图像输入。因此局部修改节省模型推理，仍需全片解码、合成与编码；UI 分开显示这两类进度。
- 所有预测写入使用原子替换；校验形状、dtype、帧数和内容校验和，损坏项当作未命中并记录。同任务仍串行执行，缓存路径沿用目录边界校验。

## 最脆弱假设与失败处理

- 单段有效试擦未必代表全片：交付一明示范围，交付三提供边界复查；不把单段满意当成全片质量证明。

- 当前 STTN 的 gap 之间独立、模型预测不依赖合成 mask：预测缓存依赖此事实。实现签名改变即失效；若以后采用跨段状态或掩码输入模型，该缓存路径必须关闭并重新设计键与上下文。
- 长视频的解码、编码和缓存容量可能成为主成本：使用有界缓存安全退化，并报告真实命中；本次不承诺所有长视频获得局部重算收益。
- 本地磁盘满：缓存写入可降级；输入、清单或正式结果写入失败则停止并保留上一成功状态，不能继续显示保存成功。
